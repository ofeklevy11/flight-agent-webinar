# זיכרון סוכן הטיסות: אינדקס

הסוכן קורא את זה בתחילת עבודה, ואופק יכול לשאול אותו על כל קובץ בדיבור רגיל ("אילו יעדים סרקנו", "אילו בעיות היו", "מה חיפשנו בשבוע שעבר", "מה המחיר הכי זול שמצאנו לרומא").
כל הקבצים נכתבים בהוספה בלבד, עם תאריך ושעה, דרך `python tools/mem.py ...` (פקודות בראש `tools/mem.py`).

| קובץ | מה בפנים | מי כותב |
|---|---|---|
| [SEARCHES.md](SEARCHES.md) | יומן כל חיפוש אמיתי: מתי, איזה סקיל, מה חיפשנו, כמה בקשות, כמה שניות, סטטוס, איפה הקובץ | `mem.py search` בסוף כל ריצה |
| [DESTINATIONS.md](DESTINATIONS.md) | כל יעד שסרקנו, התאריכים והמחיר הזול ביותר שמצאנו (להשוואה בפעם הבאה) | `mem.py dest` |
| [PROBLEMS.md](PROBLEMS.md) | כל בעיה שנתקלנו בה תוך כדי עבודה ומה פתר אותה | `mem.py problem`, מיד כשקורה |
| [PREFERENCES.md](PREFERENCES.md) | ברירות מחדל והעדפות של אופק (יציאה מ-TLV, נוסע אחד, תיירים, שקלים, ומה שנלמד) | `mem.py pref` |
| [LEARNINGS.md](LEARNINGS.md) | עובדות טכניות על גוגל ועל המנוע שחסכו זמן | `mem.py learn` |

## לפני כל חיפוש (30 שניות)
`python tools/mem.py show problems -n 8` ו-`python tools/mem.py show prefs`.

## הכי חשוב שנלמד (קיצור)
1. **מחממים את הרשימה** (`GF.prime()`): בלי זה גוגל מחזירה כ-11 טיסות במקום כל הרשימה (למשל 75 לאתונה). זה הדבר שהכי קל לפספס.
2. תשובת שגיאה קלה מגוגל (בלי טיסות) קורית לפעמים, והמנוע מנסה שוב לבד.
3. אין צילומי מסך (החלון מוסתר), אין שליחה ל-localhost ואין לוח: התוצאה חוזרת כטקסט, נשמרת בקובץ, ו-`build_excel.py` בודק סכום בדיקה.
4. הצמד הזול ביותר הוא לא תמיד טיסה טובה: לכן הציון.
